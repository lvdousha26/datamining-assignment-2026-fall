# Laya 冻结微调实验：业绩预告 → 利好/利空/中性

> 2026-11-10｜RTX 4060 8G（零成本）｜2,398 训练 / 602 评估｜编码器冻结、只训分类头

## 一句话

**提升很明显（60.8% → 78.7%，+17.9pp），但绝对值输给 10 行关键词正则（84.6%）。**
所以「换 4090 上全参」这个决定，不该做——瓶颈不在模型容量，在任务定义。

## 1. 数据

| 项 | 数值 |
|---|---|
| 原始业绩预告 | 235,229 条 / 5,591 只 / 45 个报告期 |
| 清洗后（去重、15~200 字） | 144,094 条 |
| 抽样 | 3,000 条（利好 1,831 / 利空 1,027 / 中性 142，按原始比例分层） |
| 训练 / 评估 | 2,398 / 602（分层 8:2） |

标签来源是交易所强制的「预告类型」，零人工标注：
预增/略增/扭亏/续盈/减亏 → 利好；预减/略减/首亏/续亏/增亏 → 利空；不确定 → 中性。

文本 = `预测指标｜业绩变动`，例：
> 归属于上市公司股东的净利润｜预计2016年1-3月…净利润盈利:4,878万元-5,318.89万元,比上年同期减少0%-10%

**偏差必须写在标题上**：评估集里 **90.5%** 的正文直接写着「增长/减少/盈利/亏损」。
也就是说这个任务本质是「读懂公告里的数字方向」，不是语义情感。准确率天然会偏高。

## 2. 结果

| 方法 | 准确率 | 说明 |
|---|---|---|
| 多数类基线（全猜利好） | 61.0% | 利好占 60.96% |
| Laya 零样本 | **60.8%** | 等于没有信息量 |
| Laya 冻结微调 3 epoch | **78.7%** | +17.9pp，训练 63 秒 |
| Laya 冻结微调 6 epoch | **79.7%** | 再多 3 轮只 +1.0pp，边际收益已尽 |
| **关键词正则（10 行代码）** | **84.6%** | 见下 |

按子集拆开看，模型唯一赢的地方是「正文没写方向」：

| 子集 | n | 微调模型 | 关键词规则 |
|---|---|---|---|
| 全部 | 602 | 78.7% | **84.6%** |
| 含方向词 | 545 | 80.0% | **88.4%** |
| **无方向词** | 57 | **66.7%** | 47.4% |

模型与规则分歧的 124 条里，规则对 58.9%、模型对 30.6%——模型在关键时刻更差。

混淆矩阵（微调后，行=真实、列=预测）：

|  | 利好 | 中性 | 利空 |
|---|---|---|---|
| 利好 | **314** | 1 | 52 |
| 中性 | 1 | **21** | 7 |
| 利空 | 63 | 4 | **139** |

召回：利好 0.856 / 中性 0.724 / 利空 0.675。利好↔利空互错 115 条，是主要误差；
中性只占 4.7%，召回 0.72 已经算不错。

校准：ECE 0.084 → **0.038**（3 epoch）/ 0.069（6 epoch），置信度 0.59 → 0.85。
3 轮的校准更好，6 轮过拟合了一点。

## 3. 关键词基线（为什么它更强）

```python
if '扭亏' in t or '减亏' in t: return '利好'
if '减少' in t or '下降' in t or '亏损' in t: return '利空'
if '增长' in t or '增加' in t or '盈利' in t: return '利好'
return '中性'
```

84.6%，比模型高 5.9pp。这不奇怪：标签本来就是按「净利润同比方向」定的，
而正文把方向写成了中文数字。**模型在做一件可以用字符串匹配完成的事，还做得更差。**

## 4. 那 4090 全参要不要做

**不建议，理由是三条硬证据：**

1. 3 → 6 轮只涨 1.0pp，说明**头容量**不是瓶颈；
2. 模型在 90% 的样本上输给正则，说明**信息量**不是瓶颈——该读的都读到了，读法不对；
3. 全参微调能改的是「表征」，但这里表征已经够用（能读懂"净利润减少"），
   它改不了「标签定义与文本内容几乎同构」这个事实。

**要让大模型有用，得换任务**，而不是换显卡。两个候选：

- **换标签**：不用「预告类型」，改用「公告次日/5 日超额收益方向」。
  这样文本里没有现成答案，模型必须学「哪些措辞预示超预期」（例如"略增但低于预期"）。
  数据现成：`daily_ret.npz` + 公告日期，一天能跑通。
- **换输入**：只给「业绩变动原因」段落（管理层的解释），不给数字。
  标签仍是预告类型——这时候 66.7% 那个数字才有意义，也才是语义任务。

如果这两个方向试出来仍然打不过正则，那这个课题就该结论为「业绩预告情感分类没有建模价值」，
而不是「模型不够大」。后者的结论在任何显卡上都成立。

## 5. 复现

```bash
python scripts/laya_yjyg_prep.py --n 3000                  # 数据集 → runs/laya_yjyg/
python scripts/laya_yjyg_eval.py --tag zs_full             # 零样本基线
python -m laya.train_cli --data runs/laya_yjyg/train.csv \
    --eval runs/laya_yjyg/eval.csv --out runs/laya_yjyg/ft \
    --base multilingual --freeze-encoder --epochs 3 \
    --micro-batch 8 --grad-accum 2 --max-len 128 --head-lr 3e-4
python scripts/laya_yjyg_eval.py --model runs/laya_yjyg/ft --tag ft
```

产物：`runs/laya_yjyg/{train.csv, eval.csv, ft/, ft6/, pred_*.csv, eval_*.json}`。

## 6. 硬件账

| 配置 | 时间 | 显存 | 结果 |
|---|---|---|---|
| 4060 8G 冻结编码器，3 epoch | **63 秒** | ~4.5G | 78.7% |
| 4060 8G 冻结编码器，6 epoch | 2 分钟 | ~4.5G | 79.7% |
| 4060 8G 全参（mb=8, len=256） | — | OOM | 之前已试过，不可行 |
| 4090 24G 全参（预估） | 5~10 分钟 | ~14G | 未做，建议不做 |

2,398 条数据、128 token、冻结编码器——这是一次「一顿饭不到」的实验，
它的价值不在 78.7%，在于证明了**这个任务不值得投入更多算力**。
