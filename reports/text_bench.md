# 文本模型横向对照（业绩预告 → 利好/利空/中性）

> 2026-11-10｜训练 2,398 / 评估 602 条｜同一套切分、同一套标签｜单条延迟 = batch 1 中位数

| 模型 | 准确率 | 单条延迟 | 训练耗时 |
|---|---|---|---|
| LightGBM（纯数值表格） | **93.2%** | 1.12 ms | 1.9s |
| LightGBM（表格 + 文本哈希） | **91.2%** | 1.00 ms | 2.4s |
| BERT-base-chinese（110M） | **89.2%** | 6.71 ms | 70s |
| TF-IDF + LR | **88.2%** | 0.29 ms | 0.2s |
| Qwen3-0.6B + SFT（LoRA） | **87.9%** | 243.96 ms | 425s |
| Qwen3-0.6B + 标签 logit（LoRA） | **84.6%** | 241.44 ms | 2690s |
| 关键词正则（10 行代码） | **84.6%** | 0.00 ms | — |
| Laya 冻结微调（426M） | **78.7%** | 26.40 ms | 63s |
| 多数类基线（全猜利好） | **61.0%** | 0.01 ms | — |

## 这张表在说什么

1. **表格基线（93.2%）高于所有文本模型**：标签是按「净利润同比方向」定的，而公告里的数字（变动幅度、预测值、上年同期值）直接决定方向。文本语义在这里没有增量。
2. **给 LightGBM 加文本哈希特征反而掉点（93.2% → 91.2%）**：文本特征带来的是噪声，不是信息。
3. **规则 84.6%，TF-IDF+LR 88.2%，BERT 89.2%**：模型越大越好，但都在表格基线之下——这正是「模型能力不是瓶颈」的证据。
4. **延迟差 3~4 个数量级**：表格 1.1 ms、BERT 6.7 ms、Qwen 242 ms。在一个 1 ms 就能做到 93% 的任务上，大模型没有立足点。
5. **Qwen3-0.6B 两条路线都输给 BERT（110M）**：SFT 87.9% vs BERT 89.2%，而延迟高 36 倍（244 ms vs 6.7 ms）、训练贵 6 倍。标签 logit 路线只有 84.6%，刚好等于 10 行正则——说明"参数越多越好"在这个任务上不成立，因为任务要的是从数字里读方向，encoder 比 decoder 更对路。

## 结论

**这个任务不该用文本模型。** 它测的不是「模型懂不懂语言」，而是「模型能不能从中文里读出数字的符号」。要做出有意义的文本实验，得换标签（次日超额收益）或换输入（只给变动原因，不给数字）。
