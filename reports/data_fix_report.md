# 复权脏数据：从审计到重做全流程

> 2026-11-09｜起点：美股 AMZN 用未复权价算出「至今 −84%」→ 反查 A 股 → 发现更严重的问题 → 换数据源重建

---

## 一、一句话结论

**东财的 A 股前复权（qfq）用的是「减法复权」——历史价格减去累计分红。对高分红老股，早年价格会被压到 0 甚至负数（茅台 qfq 最小价 −143.50），导致收益率方向反转。**

整个面板已改用**后复权（hfq）**重建。代价是：A2 的收益从 11.65% 降到 6.38%，模型 IC 从 0.1360 降到 0.1303。**之前那部分收益和预测力，是数据错误给的。**

---

## 二、审计方法：用涨跌停制度做硬约束

A 股日涨跌幅有法定上限（主板 ±10%、创业板 2020-08-24 后 ±20%、科创板 ±20%、北交所 ±30%）。超出上限 +2pp、且非「上市前 5 日 / 停牌超 10 日复牌」的日收益，只可能是复权出错。

| 指标 | qfq | hfq |
|---|---|---|
| 越界日 | **40,883 处（0.355%）** | **5,669 处（0.049%）** |
| 涉及股票 | 1,336 只 | 164 只 |
| 收益区间 | −99% ~ **+4,700%** | 正常 |

## 三、根因：这不是字段 bug，是复权方法

**交叉验证**：`close` 反推的收益与 `pctChg` 字段完全一致（越界 40,527 vs 40,417 条，越界最多的 5 只完全相同）。说明不是某一个字段坏了，**两个字段同源，都基于坏掉的 qfq**。

**决定性证据**（茅台 600519）：

```
2015-01-05  close = -117.62   pctChg = +9.07%
2015-01-06  close = -121.89   pctChg = -3.63%   close反推 = +3.6%   ← 方向反了
```

负价区间里 `close[t]/close[t-1] − 1` 的**符号是相反的**：真实跌 3.63%，close 反推是涨 3.6%，因为两个负数相除得正。

负价持续到 **2021-07-14**（000937 冀中能源），所以「只用 2018 年以后数据」也躲不掉。

**受影响的不只是茅台**：66 只股票出现负价（茅台、五粮液、泸州老窖、山西汾酒、格力、中国神华…）——**全是高分红白马**，而这恰好是 A2 价值策略的重仓区。

## 四、修复：换后复权重下全市场

后复权（hfq）是**乘法复权**，价格单调向上，不会压缩到 0。验证：

| 股票 | qfq 最小价 | qfq \|r\|>11% | hfq 最小价 | hfq \|r\|>11% |
|---|---|---|---|---|
| 600519 茅台 | **−143.50** | **128 天** | 884.56 | **0 天** |
| 000933 神火 | **−0.27** | **642 天** | 39.75 | **0 天** |
| 601699 潞安 | **−1.02** | **704 天** | 36.56 | **0 天** |

执行：
1. `big_download_hfq.py`：4 进程拉 5,477 只，**11.7 分钟**，5,446 成功（31 只含负价跳过）
2. `big_features.py`：数据源默认切到 `raw_hfq`，重建面板
3. `market_verify.py`：收益矩阵同步切到 hfq

## 六、这次修复改变了什么结论

| 结论 | 变化 |
|---|---|
| A1 策略③ 11.92%/1.06 | **不变**（用指数和 ETF，不碰个股复权） |
| A2 有真实超额 | **仍成立但腰斩**：+7.33% → +4.48%，夏普 0.41 → 0.25 |
| A2 不值得配置 | **更确定了** |
| 个股模型 IC 0.10 量级 | **仍成立**：0.1360 → 0.1303 |
| 42 因子塌缩成流动性一个 bet | **不变**：illiq_ratio+illiq20 仍占权重 67% |
| 多空能做 | 仍然不能（换面板后 dev 段多空好看，但封存段结论不受影响） |

## 七、遗留问题

1. **残余 5,669 处断层**：主要是新股上市首日的 44%/无涨跌幅限制，以及停牌不足 10 日的复牌。规则还能再收紧（按板块区分上市初期天数）。
2. **旧报告的数字全部过期**：`abs_return_fix_report.md`、`long_strategy_report.md`、`cv_ridge_report.md` 里引用的 A2 与基准数字都要按本报告更新。
3. **封存段不能重验**：`lockbox_eval.py` 的 runs=1 已消耗，新模型的封存段表现无法再测。
4. **禁买清单已用新模型重生成**：`live/screen_2026-10-22.csv`，D1 505 只。
