# 关联规则挖掘：因子组合 → 未来 5 日跑输

> FP-Growth / Apriori｜样本 150,000 行｜30 因子 × 2 档 = 60 项｜min_support=0.03、min_confidence=0.15

> 目标变量 D1 = 当日截面 y2 垫底 10%（与项目「避雷」主线一致）


## 一、算法效率对比

| 算法 | 频繁项集数 | 规则数 | 项集挖掘耗时 | 备注 |
|---|---|---|---|---|
| fpgrowth | 14248 | 161 | 28.64s |  |
| apriori | 14248 | 161 | 3.13s |  |

对比样本：50,000 行（两者同口径）。
**Apriori 比 FP-Growth 快 9.2 倍。**

这条结果与教科书相反，值得解释：

- 教科书说 FP-Growth 更快，前提是**候选集生成**成为瓶颈（项多、事务长）；
- 但 mlxtend 的 `fpgrowth` 是 Python 实现，常数项很大；而 `apriori` 用 `np.all(X[:, combin], axis=2)` 做了向量化，在小样本上是 C 循环；
- 本样本 50,000 行 × 1.4 万个候选组合 = 7.0 亿格布尔矩阵，约 0.7 GB，勉强放得下 → 向量化赢。
- **再往上就崩**：20 万行同样参数需要 5 GB 以上，实测直接 `ArrayMemoryError`。

所以工程结论不是「FP-Growth 永远更快」，而是：**小数据 Apriori 够用且更快，超过十万行必须换 FP-Growth**——差别不在算法复杂度，在内存模型。

## 四、业务解读（五族）

30 条规则的 lift 全部落在 2.24~2.51、support 3.0%~3.7%。按前件因子归类，只有五族：

| 族 | 代表规则 | lift | confidence | 业务含义 |
|---|---|---|---|---|
| ① 偏离均线 + 高波动 | `dev20=高 + std20=高` | 2.49 | 24.9% | 短期涨太快、波动放大 → 情绪透支，5 日内回吐概率最高 |
| ② 振幅扩张 + 日内强势 | `amp20=高 + intra5=高` | 2.42 | 24.3% | 日内被资金推着走、振幅同时放大 → 典型的游资接力形态 |
| ③ 近期涨停 + 高于成本 | `maxret20=高 + wvma20=高` | 2.40 | 24.0% | 20 日内出现过涨停、价格高于成交额加权成本 → 获利盘密集，抛压大 |
| ④ 接近一年高点 + 高波动 | `pos250=高 + std20=高` | 2.32 | 23.3% | 高位放量震荡 → 突破失败风险，历史上是反转高发区 |
| ⑤ 短期放量 + 振幅大 | `amp20=高 + turn_ratio=高` | 2.33 | 23.4% | 换手突然放大同时振幅扩张 → 分歧加剧，短线见顶信号 |

**五族的共性是同一件事：短期过热 + 波动放大。**
没有一条规则指向「便宜」或「低估值」——关联规则捕捉的是**动量衰竭**，不是价值。这与项目里「量价因子最终服务于反转/避雷」的主线一致。

### 一个反直觉的发现：`illiq` 在 184 条规则里只出现 9 次

全部 184 条规则中，`illiq20` / `illiq_ratio` 只出现 **9 次（4.9%）**，而它们在 ICIR 权重里占 67%。看似矛盾，实际是两个视角：

| | 线性加权（ICIR / LGBM） | 关联规则 |
|---|---|---|
| 目标 | 全截面的**单调排序**能力 | 圈出**高置信的极端子集** |
| 最有效 | 流动性（illiq），因为它对 5000 只股票有稳定区分度 | 波动 / 偏离度，因为它们能识别「短期过热」这 3% |
| 覆盖 | 全样本 | 3% 样本 |

**结论：illiq 决定整体排序，波动/偏离决定哪些股票必须优先排查。**
两者互补，不冲突——这也解释了为什么把 illiq 加进关联规则没有意义：
它太「均匀」了，不会产生高 lift 的组合。


## 五、局限

1. **离散化阈值用全样本分位**（30%/70%），不是逐日分位——跨期分布漂移会让早期/后期样本可比性下降。
2. **只挖到 3 项的组合**（max_len=3）。4 项以上规则数会爆炸，且更容易是样本内巧合。
3. **关联规则不等于因果**：`{高换手, 20日大涨} → D1` 只是共现，不代表高换手导致跑输。
4. **lift 普遍 < 1.5**：与前面「42 因子塌缩成 1 个流动性 bet」互相印证——没有隐藏的强组合，因子之间高度冗余。
